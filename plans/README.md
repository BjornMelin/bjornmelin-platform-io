## Findings considered and rejected

- Full visual redesign: rejected because the production interface is already cohesive, responsive,
  and visually authored. This lane is corrective polish, not replacement.
- Add Motion, GSAP, or Three.js: rejected because no interaction needs those runtime dependencies.
  Base UI and targeted CSS transitions already own the relevant motion.
- Virtualize or memoize the project and skill grids: rejected because the current 20-project and
  66-skill datasets have no measured rendering bottleneck.
- Wholesale shadcn overwrite: rejected because current wrappers encode the completed Base UI hard
  cut and upstream button motion includes `transition-all`, which conflicts with repository rules.
- Split the static About component solely for file length: rejected because no correctness,
  ownership, or measured performance defect was found.
- Replace the unused custom error boundary in this pass: deferred because the user-visible identity,
  navigation, theme, and catalog defects have greater leverage. Track native App Router error
  handling in a later reliability PR.
- Add desktop active-navigation state in this pass: deferred to avoid broadening the shell change
  while the higher-impact theme accessibility correction is under review.
- Change the global reduced-motion rule: rejected because its conservative near-zero-duration
  behavior is accessible and no broken interaction was reproduced.
- Add transform-origin classes to select and dropdown popups: deferred because production placement
  and animation remained stable in direct interaction testing; a library-source difference alone is
  not enough reason to churn the wrappers.
